## 2. 實測通道分析

### 2.1 錄音條件
- **源檔案**: `ambient_60s.wav`
- **持續時間**: 60 秒
- **環境**: 室內環境噪音（空調、風扇等背景聲）
- **檔案大小**: 3.7 MB (960,000 样本 × 2 通道 × 16-bit)

### 2.2 每通道信號品質

#### Channel 0
- **RMS**: 2873.13 (顯著信號)
- **狀態**: ✓ 非零
- **包絡穩定性** (CV): 1.0608 → ✓ **無 AGC 痕跡**
- **頻譜峰值**: 121.1 Hz (PSD 47.4 dB)
- **能量分佈**:
  - 100-3k Hz: 32.1 dB (主要能量)
  - 3k-8k Hz: 21.0 dB
  - >8k Hz: 稀疏

#### Channel 1
- **RMS**: 408.36 (弱信號，可能是邊際通道)
- **狀態**: ✓ 非零
- **包絡穩定性** (CV): 0.7076 → ✓ **無 AGC 痕跡**
- **頻譜峰值**: 121.1 Hz (PSD 32.9 dB)
- **能量分佈**:
  - 100-3k Hz: 14.1 dB (弱)
  - 3k-8k Hz: 2.3 dB (極弱)
  - >8k Hz: 稀疏

### 2.3 通道獨立性分析

| 分析項 | 實測值 | 解釋 |
|--------|-------|------|
| **Ch0 ↔ Ch1 相關係數** | 0.8092 | 中等相關 (0.3-0.9) |
| **是否為複製** | ✗ 否 | 相關係數 < 0.95，排除單路複製 |
| **獨立性評價** | ≈ 相對獨立 | 兩通道信號不同 (RMS 差 7 倍)，但仍有相關性 |

**解釋**: 
- 兩通道不是同一路複製，而是來自不同的麥克風陣列位置
- 中等相關性 (0.8) 可能來自：
  1. 共同的環境背景噪音 (空調、風扇等)
  2. 麥克風之間的交叉耦合
  3. 可能的固件內混合處理 (未確認)

## 3. AGC/降噪痕跡檢查

### 分析方法
計算 500ms 滑動視窗 RMS 包絡的變異係數 (CV):
- CV > 0.15 → 正常自然變異 (無 AGC)
- CV 0.05-0.15 → 輕度 AGC
- CV < 0.05 → 強烈 AGC（自動拉平）

### 實測結果

| 通道 | 包絡均值 | 包絡標準差 | CV | 判定 |
|------|---------|-----------|-----|------|
| Ch 0 | 1977.74 | 2097.91 | 1.0608 | ✓ **無 AGC** |
| Ch 1 | 334.27 | 236.53 | 0.7076 | ✓ **無 AGC** |

**結論**: 兩個通道的 RMS 包絡均顯示正常變異，**未檢測到自動增益控制或動態降噪**。
這表明拿到的 2 個通道是相對「乾淨」的信號，至少在 ALSA 層級沒有明顯的動態處理。

## 4. 實際頻寬驗證

### 4.1 Nyquist 採樣限制
採樣率 16 kHz → Nyquist 頻率 = 8 kHz

### 4.2 實測頻譜特性

**Channel 0** (強信號):
- 峰值在 121 Hz（低頻背景噪音，可能來自環境 AC/HVAC）
- 3-8 kHz 能量 21.0 dB（中等）
- 超過 8 kHz：數據點稀疏（接近 Nyquist）

**Channel 1** (弱信號):
- 峰值也在 121 Hz
- 3-8 kHz 能量 2.3 dB（極弱）
- 超過 8 kHz：幾乎無能量

### 4.3 有效頻寬評估
- **有效上限**: 約 8 kHz (Nyquist 限制)
- **實際內容**: 主要在 100-3000 Hz，3-8 kHz 有次要能量
- **語音頻率覆蓋**: ✓ 充分 (語音主要在 80-8000 Hz)
- **高頻細節**: ✗ 受限 (無法捕捉 >8 kHz 的聲源定位細節)

## 5. 判定與結論

### 5.1 核心問題：能否拿到 4 個同時、獨立、未經 AGC 的 raw microphone 通道？

## **判定: FAIL**

### 詳細理由:

| 準則 | 需求 | 實測 | 狀態 |
|------|------|------|------|
| **通道數量** | ≥ 4 獨立通道 | **2 通道** | ✗ **不足** |
| **信號獨立性** | 互相獨立，非複製 | 相關 0.8092，相對獨立 | ≈ 部分滿足 |
| **AGC 狀態** | 無動態增益控制 | CV > 0.15，無 AGC | ✓ **滿足** |

### 5.2 根本原因分析

**Seeed XVF3800 韌體架構**:
```
硬體: 4 顆麥克風 + DSP (Vesper VT1468)
             ↓
ALSA 韌體 (v2.05): 將信號映射到 2 個 USB 通道
  - 可能的配置:
    * Ch0: 前向 mic pair 或 beamforming 結果
    * Ch1: 側向 mic pair 或次級 beamforming
    * Ch2-3: 在 DSP 侧處理（降噪/AEC），不暴露給 ALSA
             ↓
Linux ALSA Host: 只能看到 2 ch
```

**訪問 4 個原始通道的方式**:
1. **透過 Seeed xvf_host SDK** (已驗證無此工具)
2. **透過特殊固件版本** (未評估，需重刷)
3. **透過 JACK/PulseAudio 插件** (已驗證無此配置)

**當前環境現狀**:
- ✗ 無 `xvf_host` 工具（需安裝 Seeed SDK）
- ✗ 無客製 ALSA 配置檔
- ✗ 無 JACK
- ✓ 有基礎 ALSA 工具鏈

## 7. 下一步建議

### 7.1 若要繼續用 XVF3800 達成目標

**Option A: 安裝 Seeed SDK + xvf_host** (最可行)
```bash
# 預計步驟 (未執行，防止系統變動)
1. 下載 Seeed xvf_firmware_tool + xvf_host
2. 編譯/安裝 xvf_host 到 /usr/local/bin/
3. 重新測試: xvf_host -c 4 -r 16000 | ... (解鎖 4ch)
4. 重複本評估流程，驗證 4ch 獨立性 & AGC
```
**預期**: 應能拿到 4 個 raw 通道，但需驗證 AGC 狀態和頻寬
**風險**: xvf_host 二進制檔相容性、額外依賴

---

**Option B: 重刷特殊固件** (高風險，無法執行)
```
1. 下載 Seeed XVF3800 4ch raw 固件版本
2. 用 xvf_device_firmware_updater 重刷
3. 重測通道數和獨立性
```
**預期**: ALSA 可能暴露 4 個通道
**風險**: 固件不相容、功能喪失、無法回滾（任務禁止）
**現狀**: **不執行**（範圍限制）

---

**Option C: 用現有 2 通道做 Fallback（立即可行）**
- **方案**: 利用 XVF3800 內建的 **360° 方向搜索能力**（板載 DSP 做 beamforming）
- **流程**:
  1. 啟用 XVF3800 的 DoA (Direction-of-Arrival) 輸出
  2. 用 Seeed xvf_host 或 PulseAudio 外掛讀取 DoA 結果（方位角 0-360°）
  3. 結合本地 qwen inference，不需 4ch raw 也能做方向感知原型
  4. 後續用 SoundCam 3 擴展為 8-16ch beamforming

- **優點**: 立即可行、無韌體改動、保留 2ch raw 通道
- **缺點**: DoA 精度取決於 XVF3800 內建算法（通常 ±5-10°）
- **成本**: 低

---

### 7.2 建議優先級

1. **P0: 安裝 xvf_host** → 驗證 4ch 是否可得
   - 若成功 → 進入 "原型 beamforming 研發"
   - 若失敗 → 進入 P1

2. **P1: 啟用板載 DoA**（XVF3800 內建）→ 做 360° 方位原型
   - 集成到 brain 的顧問流（類似 Gemini 查詢機制）
   - 近期內可交付，精度 5-10°，夠做基礎原型

3. **P2: 後期遷移**→ 換上 SoundCam 3 或 ReSpeaker 更新款
   - 當需要 >8 kHz 頻寬或 8+ 通道時
