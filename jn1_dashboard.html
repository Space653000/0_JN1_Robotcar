📋 為什麼 on-device moondream2 結案（誠實版）

9 次嘗試每次都是不同的真實障礙：compose 指不對 → 缺 transformers → numpy 2.x 衝突 → build 時 DNS 解不到 → 最強打法（不 build、直跑 base image）第一次摸到模型載入機制，撞到真牆：moondream2 需 trust_remote_code，在離線＋容器無 pip 網路下，transformers 動態模組解不了它的自訂程式碼（FileNotFoundError: layers.py）。這是框架契合問題，不是硬體/模型不相容。已證明：torch+CUDA 可用、numpy 診斷正確、模型檔無損、隔離測試全程生產零損傷。未來便宜路＝ollama pull moondream（原生 GGUF，繞開 transformers）。

🎯 JN1 聲學定位：能做到什麼、做不到什麼（誠實版）

能用且穩定：即時相機（聲學前端向 perception 拿 /frame.jpg，與視覺服務共用同一支 C922、零搶相機、零風險）、對數頻譜 20Hz–8kHz、時頻圖、聲音分類（實驗）、相對音量、一鍵校準按鈕；修掉反轉的 sleep 公式後 fps 1.6→20。做不到（硬體天花板）：360° 方向雷達——能讀的 2 個 USB 通道是 XVF3800 的處理後波束（會議＋ASR）、不是有幾何間距的原始麥克風，板載 DoA 又讀不到（無 xvf_host/SDK）→ 方向近乎常數、卡死，任何 smoothing/演算法都救不了，誠實標「實驗」。要靈敏又準需 raw 4-mic 或換陣列（未來硬體）。分支 jn1-work，已整併統一首頁兩頁籤＋HTTP Basic Auth 登入＋Cloudflare Tunnel 上網。
