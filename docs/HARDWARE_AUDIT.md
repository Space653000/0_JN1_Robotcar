## 四、餘裕評估 & 能力邊界

### 4.1 當前狀況：「視覺+對話+自然描述」

**能否穩定同時運行？**
- ✅ **短期可以**（已驗證）
- YOLO 檢測：45ms，穩定
- qwen 自然句生成：2-5s（模型加載+推論）
- 序列化設計避免競爭
- GPU VRAM 邊界但可控

**OOM 風險？**
- ❌ **當前設計已避免**
  - 模型按需卸載（OLLAMA_MAX_LOADED_MODELS=1）
  - 容器內存限制未超
  - 系統可用 6.6 GiB 緩衝
- ⚠️ **風險來源**
  - 模型卸載延遲（3-5s）
  - 同時加載多個大模型會觸發 OOM
  - 長期運行內存洩漏（如未正確釋放）

### 4.2 頂級升級可行性分析

#### 目標：「頂級語音+視覺+代理大腦」

需要部署的組件：
```
頂級 ASR (Whisper-Large):     ~3.5 GiB
頂級 TTS (漢語特化):          ~1.5 GiB  
代理大腦 (Continuous):        ~2.0 GiB (需持續GPU推論)

YOLO 檢測 (常駐):            ~0.5 GiB
─────────────────────────────────
總需求:                      ~12.2 GiB (GPU/系統混合)
```

**當前瓶頸分析**：

| 資源 | 現狀 | 需求 | 評估 |
|------|------|------|------|
| **系統 RAM** | 6.6 GiB 可用 | 3-4 GiB | ✅ 可行 |
| **GPU VRAM** | 15.3 GiB | 12 GiB+ | ⚠️ 緊張 |
| **CPU 核心** | 8×A78 | 4-6 核 | ✅ 足夠 |
| **磁盤** | 444 GiB | 100 GiB | ✅ 足夠 |
| **功耗** | MAXN_SUPER | 15W+ | ✅ 支持 |
| **散熱** | 47°C | <70°C | ✅ 充足 |

**結論**：
- ✅ **短期升級（3 個月內）**：可以
  - 升級 ASR 到 Whisper-small
  - 持續 qwen 推論
  - 按需 YOLO + VLM
  - 需要精心管理 GPU 記憶體切換

- ⚠️ **中期升級（6 個月內）**：可能需要調整
  - Whisper-medium 會導致頻繁模型卸載
  - VLM 常駐會擠壓 qwen 空間
  - 代理大腦持續推論會消耗 GPU 40-60%

- ❌ **完整頂級配置**：現有硬體不夠
  - 不能同時常駐：whisper-large + qwen + llava + 代理推論
  - 需要 24GB+ GPU VRAM 或分佈式架構

## 五、具體建議 & 優化方案

### 5.1 短期內優化（立即可做）

#### 1. **YOLO 推論加速** → TensorRT Engine
```
當前：YOLO11n (PyTorch) 在 GPU 上
目標：轉換為 TensorRT Engine，減少記憶體 20-30%
方法：使用 trtexec 或 NVIDIA 轉換工具
預期收益：GPU VRAM 從 15.3 -> 12 GiB 可用
```

#### 2. **qwen 常駐優化**
```
當前：按需加載/卸載（3-5s 延遲）
目標：啟用 qwen 和 llava 共存（輪流使用）
方法：增加 OLLAMA_MAX_LOADED_MODELS=2，調整 KEEP_ALIVE
風險：可能觸發 OOM，需測試
```

#### 3. **模型緩存優化**
```
當前：所有模型存於 /data/ollama/models（可變位置）
目標：確保 qwen + llava blob 優先緩存（減少加載延遲）
方法：定期 `docker exec ollama-new ollama pull qwen2.5:3b` 預熱
```

#### 4. **代理推論 Warm-up**
```
當前：Cold start 時 LLM 初始化 1-2s
目標：Server startup 時執行 dummy inference
實現位置：brain startup 時呼叫一次 qwen
預期：首次使用者查詢不再遇到冷啟動延遲
```

### 5.2 中期升級方案（1-2 個月）

#### 方案 A：「輕量級頂級」（推薦）
```
✅ ASR:       Whisper-small (1.5 GiB) ← 替換 sensevoice
✅ TTS:       高質量中文 TTS (1.2 GiB) ← 替換 Kokoro
✅ YOLO:      TensorRT 優化版 (0.3 GiB)
✅ qwen:      保留 2.5:3b
✅ 代理:      純 LLM 推論（無獨立大模型）
────────────────────────────────
合計：~5.2 GiB GPU + 2.0 GiB 系統 = 可行

約束：VLM (vision) 按需卸載，不常駐
```

#### 方案 B：「完整頂級」（不推薦，需升級硬體）
```
❌ 需求超過現有硬體
   - Whisper-large: 3.5 GiB
   - 高質量 TTS: 1.5 GiB
   - qwen + llava 常駐: 6.7 GiB
   - 代理推論: 2.0 GiB
   - ────────────────
   - 總計: 13.7 GiB (超過 GPU VRAM 15.3 的安全線)

建議：升級至 Jetson Orin Nano 24GB 或 Orin NX + 外接 GPU
```

### 5.3 長期架構優化

#### 1. **分佈式推論**
- Brain 層：qwen（輕量推論）+ 本地
- Cloud 層：llava / whisper-large（按需調用）
- 通訊：gRPC 或 HTTP，<500ms RTT

#### 2. **模型量化**
- YOLO：INT8 量化（已可做）
- qwen：4-bit 量化（減少 50% VRAM）
- llava：INT8（減少 30% VRAM）

#### 3. **動態資源管理**
- 監控 GPU VRAM 實時使用率
- 自動卸載低優先級模型
- 優先級：YOLO > 代理 > qwen > vision

## 六、風險評估

| 風險 | 概率 | 影響 | 緩解方案 |
|------|------|------|---------|
| CUDA OOM 在推論峰值 | 中 | 服務中斷 | 模型切換、加入隊列限制 |
| 模型加載延遲過長 | 中 | 使用體驗下降 | Warm-up + 提前預載 |
| GPU VRAM 洩漏 | 低 | 長期服務下降 | 定期重啟 ollama、監控指標 |
| 散熱不足（高負荷） | 低 | 頻率降速 | 加裝風扇、監控溫度 |
| 磁盤滿（模型佔用） | 極低 | 模型無法緩存 | 定期清理、擴容至 1TB |

## 七、最終結論

### ✅ 現狀能力評估

**「頂級語音+視覺+代理大腦」的承載**：
- ✅ **視覺**（YOLO 檢測 + 自然描述）：**完全可行** ⭐⭐⭐⭐⭐
  - 單幀推論穩定 45ms
  - 自然句生成已驗證
  - GPU 記憶體管理良好

- ✅ **語音**（ASR + TTS）：**基本可行，可升級** ⭐⭐⭐⭐
  - 當前 SenseVoice + Kokoro 穩定運行
  - 可升級到 Whisper-small + 高質量 TTS
  - Whisper-large + TTS-Large 會觸發頻繁卸載

- ⚠️ **代理大腦**（持續推論）：**部分可行，需謹慎** ⭐⭐⭐
  - 單次推論（qwen）可行
  - 持續推論（代理循環）會競爭 GPU VRAM
  - 不建議同時啟用 VLM 和代理推論

### ❌ 現狀瓶頸

1. **GPU VRAM 15.3 GiB**：遠不夠同時載入「頂級語音+VLM+代理」
2. **模型切換延遲 3-5s**：影響互動流暢度
3. **OLLAMA_MAX_LOADED_MODELS=1**：無法同時持有 qwen + llava

### 💡 建議路徑

**立即可做**（硬體不變）：
1. YOLO → TensorRT 優化（減少 GPU 佔用 20%）
2. 啟用 qwen 常駐 + llava 按需卸載
3. 代理大腦採用「輕推論」模式（少於 2s 單次）

**短期升級**（1-2 個月，不需換硬體）：
1. ASR 升級到 Whisper-small
2. TTS 升級到中文特化模型
3. 代理大腦持續推論模式（監控 GPU）

**中期方案**（需考慮硬體升級）：
1. 若要 Whisper-large + qwen + llava 同駐 → Jetson Orin NX 24GB
2. 若要分佈式 → 本地 + Cloud 協作
